# Настройки напоминаний и режим «Я играю»

Проверенный этап КД зафиксирован локальным коммитом `fc64780` поверх аккаунтов `9dcac43`. Текущая ветка — `feat/player-event-reminders`. Из коммита исключены исходные изменения папок Media, их import map, относящиеся к ним генерируемые типы и проверки папок; рабочие файлы сохранены. Реализация напоминаний остаётся незакоммиченной для просмотра.

## Что добавлено

На `/events/[slug]` — кнопка «Напомнить». Гостю предлагается вход с возвратом на ивент. Игроку открывается существующий Radix Dialog: предупреждение за 5/10/15/30 минут или целое 1–120, по умолчанию 10; «Один запуск»/«Пока я играю»; показывать КД, по умолчанию включено; сохранение и отмена. Есть подписи, автофокус, Escape, восстановление фокуса, прокрутка на мобильном экране, загрузка, ошибки и защита повторного нажатия. Общий Dialog получил необязательный closeLabel и экспорт штатного Trigger; прежний поиск сохраняет свой текст закрытия.

В `/account` добавлены «Напоминания» и «Я играю». Для подписок есть редактирование, временное отключение и удаление; разовые и регулярные настройки имеют отдельные пустые состояния. Ивент может одновременно иметь оба типа настройки. UI честно сообщает: «Настройки сохранены. Отправка сообщений пока не подключена». Никакой доставки, обещаний получения сообщения или кнопок несуществующих каналов нет.

## Хранение

`player-event-reminders`: player, event, kind (once/regular), leadMinutes, includeCooldown, enabled, выбранные launchAt/remindAt для once, revision и скрытый requestID. Уникальный составной индекс player/event/kind. В regular даты запуска не сохраняются: ближайший подходящий экземпляр рассчитывается по актуальному расписанию. Подписки переживают игровые периоды и выход из аккаунта.

`player-play-sessions`: уникальный player, startedAt/endsAt (UTC), revision, скрытый requestID. Это один текущий период, без истории. Включение — 2/4/6 часов, UI по умолчанию 4. Продление — только активному периоду на 1/2 часа от сохранённого конца. Выключение ставит endsAt в серверное текущее время. После endsAt режим считается выключенным при любом чтении — без фоновой задачи. Закрытие сайта/выход его не выключают. Сохранение подписки режим не включает.

Обе коллекции типизированы отдельными файлами; схемы и индексы создаёт Payload, ручных таблиц SQL нет. Личный КД в настройки не копируется. При каждом чтении/предпросмотре запрашивается актуальный собственный player-event-cooldowns; cancelled/истёкший КД не считается активным.

## Расчёт запусков

Повторно используется `expandLaunches` из существующей логики расписания. HH:mm всегда трактуется как фиксированное серверное UTC+3. Перебираются реальные календарные даты, включая полночь; зона игрока влияет только на форматирование через общий time-zone store и formatLaunch, не на сохранённые UTC-моменты.

Разовое предложение — ближайший запуск со строго будущим временем предупреждения. При 18:18, запуске 18:25 и предупреждении за 10 минут выбирается следующий подходящий запуск, без немедленной отправки. В диалоге перед сохранением видны запуск, предупреждение и зона. Сервер повторяет расчёт при записи, проверяет действительное расписание и актуальность времени; при устаревшем предложении возвращает 409 с обновлённым предложением. UI показывает его и требует повторного сохранения, не переносит молча. Сохранённый once привязан к конкретному instant, не пересчитывается при смене зоны/игрового периода. После remindAt — «Время напоминания прошло», без статуса «отправлено» и без автоматического переноса.

Если выбранный запуск исчез из расписания или ивент недоступен, once помечается как требующий перевыбора. Сохранённые моменты остаются прежними. Без расписания новая настройка недоступна. Регулярная подписка использует текущее расписание. При выключенной игре — «Ожидает включения “Я играю”», при выключенной подписке — «Подписка отключена», при отсутствии экземпляра в оставшемся периоде — отдельное сообщение.

Период игры трактуется как [startedAt, endsAt). И предупреждение, и сам запуск должны быть внутри него; запуск ровно на endsAt уже не включён. Пропущенные до включения/текущего времени предупреждения не догоняются. Разовые настройки от периода игры не зависят.

КД **никогда не участвует в отборе запусков**. Галочка управляет только будущим текстом. Предпросмотр показывает ивент и запуск; при включённой галочке — актуальный конец КД, пояснение «к запуску КД закончится» либо примерную разницу в минутах после начала и осторожное «если ивент ещё будет доступен». Без активного КД — «Активного КД нет». При выключенной галочке текст сообщения не содержит сведений о КД. Это пример: при будущей отправке данные нужно читать заново. Длительность ивента не добавлена.

## Серверные операции и защита

- `GET /api/account/reminders` — собственные настройки и текущий период. `eventID` необязательно ограничивает список ивентом.
- `GET ...?preview=1&eventID=...&kind=once|regular&leadMinutes=...` — серверное предложение, текущая версия и актуальный КД.
- `POST` action save/delete/toggle/play — только разрешённые поля. Для save принимается предложенный launchAt, но он обязательно сравнивается с результатом серверного расчёта; remindAt, player ID, startedAt, endsAt и произвольные результаты клиент задавать не может.

Игрок определяется HttpOnly-сессией Players. Guests/Users не читают чужие персональные настройки. Стандартный Payload REST/GraphQL допускает только собственное чтение; прямые create/update/delete закрыты. Внутренние операции используют Symbol-capability, недоступный JSON-клиенту; хуки дополнительно запрещают обход при неверном доверенном CRUD. Связи maxDepth:0 не раскрывают приватные документы Players. Новых прав админки/ролей нет.

Все операции сериализуются транзакционной advisory-блокировкой PostgreSQL по игроку. CRUD с user/req и overrideAccess:false; узкие чтения скрытого requestID уже найденного собственного документа выполняются с обоснованным overrideAccess:true. Повтор текущего requestID возвращает состояние без повторной записи; revision защищает от устаревшего изменения. Продление с повторно доставленным идентификатором не прибавляет время дважды. Индексы дополнительно исключают дубли. Хранится только последний идентификатор и текущая версия, не история операций.

POST требует точный Origin, JSON и ограничивает тело 2048 байтами при чтении потока. Лимиты — 600 записей на процесс, 120 на игрока за 15 минут. Как в аккаунтах/КД, HTTP-счётчики локальны процессу; для нескольких инстансов нужен общий limiter. Транзакционная целостность сохраняется через общую PostgreSQL.

Ответы — private,no-store,max-age=0 и Vary:Cookie, SSR существующих страниц динамический. Персональные данные не хранятся в localStorage/общем кэше. Focus/visibilitychange/pageshow перечитывают серверное состояние, на время проверки скрывают старый снимок. При другой сессии/ошибке верификации прежние данные не показываются. Таймер опирается на серверный timestamp и monotonic elapsed время. Истечение режима и once отображается без reload; при наступлении показанного регулярного предупреждения запрашивается следующее предложение. WebSocket, cron, очередь и реальная отправка отсутствуют.

## Применение схемы и запуск

Сохранён development schema push. Добавляются две коллекции, индексы и служебные связи Payload; текущие игровые данные/расписания не преобразуются. Миграции не вводятся, сбросы и удаления данных не выполняются. Перед применением на рабочей базе нужна актуальная резервная копия PostgreSQL; `pnpm dev` может применить добавочную схему, в том числе при обновлении конфигурации уже работающего dev-сервера. Не подтверждать reset, удаление/переименование существующих таблиц/колонок. Production schema push по-прежнему выключен; переход к миграциям и развёртывание — отдельный этап.

Новых env-переменных и зависимостей нет. Используются DATABASE_URL/PAYLOAD_SECRET, тесты с записью — только валидируемая отдельная EVIL_TEST_DATABASE_URL с суффиксом `_test`. Браузерные тесты работают на 3101 с `.next-player-tests`; рабочий dev-сервер не используется для тестовых записей. Новых страниц нет, SEO существующих account/event сохранено.

## Ручной сценарий

1. В `http://localhost:3000/events` открыть существующий ивент с расписанием. Гостем нажать ссылку входа с возвратом, игроком — «Напомнить». Проверить default 10 минут/галочку, custom 1–120, Tab/Shift+Tab, Escape/возврат фокуса, телефон и обе темы.
2. Сохранить разовое напоминание: сверить запуск/предупреждение/часовой пояс. При устаревшем предупреждении увидеть новое предложение и подтвердить его повторно. Если расписания нет, сохранение недоступно.
3. Создать регулярную подписку на тот же ивент. В `http://localhost:3000/account` увидеть обе настройки; режим сам не включается. Редактировать, отключить/включить подписку, удалить с подтверждением.
4. Включить «Я играю» на 4 часа, продлить от текущего конца, выключить. Проверить сохранение после выхода/входа и во втором браузере. После окончания остаётся новое включение, продление скрыто. Подписки сохраняются.
5. Проверить предпросмотр с КД до/после старта, без активного КД и с выключенной галочкой. КД не меняет выбранный запуск. Смена зоны меняет подписи, а не UTC-моменты once.
6. Проверить пустые состояния, ошибки сети и обновление по возврату на вкладку. Проверить прежние вход/профиль/КД и вход администратора. Рабочие расписания ради теста не менять: крайние сценарии воспроизводятся изолированными фикстурами.

Истёкшие предупреждения не догонять. Изменения режима и отмены должны учитываться перед доставкой.

Once и regular одного игрока могут указывать на один запуск/момент предупреждения. Будущая очередь обязана дедуплицировать доставку по игроку + ивенту + конкретному запуску + времени предупреждения + каналу, независимо от источника once/regular. Если настройки текста различаются, приоритет нужно согласовать до реализации отправки; два одинаковых сообщения отправлять нельзя. Сейчас очередь и статусы отправки не создаются. Уведомление только об окончании КД — отдельная будущая опция.
