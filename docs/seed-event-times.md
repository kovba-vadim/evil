# Одноразовое заполнение времени запусков

Скрипт `scripts/seed-event-times.ts` содержит согласованный список из 111 уникальных
значений HH:mm по серверу UTC+3. Часовой пояс машины не используется. Времени 05:00
в списке нет.

Запускать из корня проекта с существующим локальным `.env` (`DATABASE_URL`,
`PAYLOAD_SECRET`) и доступным PostgreSQL. Подключение берётся из `src/payload.config.ts`.

```sh
# Только проверка списка, без подключения к БД
pnpm seed:event-times --check

# Предпросмотр: читает БД и считает существующие/недостающие времена, без записи
pnpm seed:event-times

# Создание недостающих записей — только после отдельного подтверждения пользователя
pnpm seed:event-times --apply
```

При заполнении используются только `find` и `create` Payload Local API. Это доверенная
административная операция с явным `overrideAccess: true`. Штатный хук коллекции
вычисляет `minutes`; поля, валидация и уникальность `time` сохраняются. Новых полей
и миграций нет. Как и в существующем backfill-скрипте, `PAYLOAD_MIGRATING=true`
устанавливается только внутри процесса, чтобы отключить development schema push.
Существующая схема коллекции должна быть уже применена.

Существующие записи, включая времена вне списка и 05:00, остаются без изменений.
Ивенты и их связи не изменяются. При повторном запуске все уже существующие времена
пропускаются. Если запуск прервался, созданные записи сохраняются, и повторный запуск
добавит оставшиеся. Уникальный индекс `time` защищает от дублей, в том числе при
одновременных запусках; один из конкурирующих запусков может завершиться ошибкой.

В конце выводятся количества существовавших, недостающих и созданных записей.
После заполнения проверьте справочник «Время запусков» в админке: значения HH:mm,
вычисленные минуты и сохранность прежних связей. Автоматические тесты скрипта
проверяют логику на подменённом API без записи в PostgreSQL.
