# Одноразовое заполнение ивентов

`scripts/seed-events.ts` содержит 14 согласованных ивентов и 111 запусков.
Времена — буквальные HH:mm по серверу UTC+3. Расписание ежедневное: даты,
перевод часового пояса и смещение следующего дня в Payload не сохраняются.

Запуск из корня проекта с существующим `.env` (`DATABASE_URL`, `PAYLOAD_SECRET`):

```sh
# Проверка расписания, без подключения к БД
pnpm seed:events --check

# Предпросмотр, только чтение
pnpm seed:events

# После отдельного подтверждения пользователя — запись
pnpm seed:events --apply
```

Предпросмотр показывает количество новых/существующих ивентов, количество
недостающих связей (включая связи новых ивентов) и для каждого ивента действие
и добавляемые времена. Если справочник пуст или неполон, сначала отдельно
заполните его по инструкции `seed-event-times.md`. Скрипт ивентов времена не создаёт.

Ивент ищется по названию или slug, вычисленному общей функцией проекта.
Несколько совпадений или одна запись, подходящая нескольким строкам расписания,
считаются неоднозначностью: скрипт останавливается до записи. Новые записи получают
нулевые монеты и КД, пустые описания/награды; slug генерирует существующий хук Payload.
Существующим записям передаётся только объединённый список launchTimes. Название,
slug, монеты, КД, описания, награды и дополнительные прежние времена сохраняются.
Если дополнений нет, update не вызывается.

До записи проверяется наличие всех 111 времён. Все чтения и записи в режиме
заполнения выполняются в одной транзакции через Local API с явным
`overrideAccess: true` для доверенной административной операции. Хуки получают
тот же req; ошибка приводит к откату всей транзакции. Повторный запуск не добавляет
дубликаты. Запускайте один экземпляр и не редактируйте расписания одновременно
со скриптом: транзакция не является блокировкой параллельных редакторов.

Схема должна быть уже применена. Скрипт устанавливает PAYLOAD_MIGRATING=true
только для своего процесса, отключая development schema push, и запрещает
PAYLOAD_DROP_DATABASE=true. Схема, коллекции и подключение PostgreSQL не меняются.
Секреты и сырые ошибки драйвера не печатаются.

Проверки без БД находятся в tests/int/seedEvents.int.spec.ts; проверка Local API,
связей, генерации slug, отката и повторного запуска — в
tests/payload/seed-events.payload.spec.ts, только на EVIL_TEST_DATABASE_URL.
После реального заполнения проверьте времена и сохранность контента в локальной
админке. Сам CLI с --apply агент без отдельного подтверждения не запускает.
