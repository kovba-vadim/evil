# Agents

This project uses the Payload CMS skill at `.agents/skills/payload/`.
Start with `.agents/skills/payload/SKILL.md` for a quick reference, then see `.agents/skills/payload/reference/` for detailed docs.

## Правила проекта Evil

- Перед работой прочитай `docs/data-model.md` и соответствующие разделы навыка Payload.
- Модель данных и стандартная админка Payload реализованы. Разработка публичного фронтенда разрешена в рамках конкретных заданий; согласованные требования и этапы — в `docs/frontend-plan.md`. Не реализовывать последующие этапы, фильтры и пересчёт часовых поясов без соответствующей задачи.
- Сохраняй существующую структуру Payload + Next.js, Users, Media, PostgreSQL и локальный запуск. Docker не требуется. Не переносить FSD, Sass helpers или архитектуру из других проектов.
- Существующие версии зависимостей не обновлять без задачи. Используй pnpm и существующий lockfile.
- Коллекции описывать типизированными конфигурациями Payload в отдельных файлах. Не создавать таблицы вручную SQL-запросами.
- Технические имена полей и slug коллекций — английские, подписи и пояснения админки — русские.
- Events — ивенты по ежедневному расписанию. Quests — квесты без расписания. Не менять эти значения местами.
- Следуй согласованной модели. Не добавляй игровые механики, уровни, вероятности выпадения, роли, аккаунты посетителей или личные таймеры без отдельной задачи.
- Не добавляй игровые записи и seed-данные без задания. Примерные рецепты не считать достоверными данными.
- Связь хранить в одном месте; обратные списки получать запросами или подходящими join-полями Payload. Не синхронизировать два вручную редактируемых списка.
- Использовать встроенные поля и интерфейс Payload. Общие определения полей выделять только при реальном повторении.
- Запись и удаление контента доступны только аутентифицированным пользователям админки. Публичное чтение определить отдельной явной настройкой; Users не открывать публично.
- В новых CRUD-вызовах Local API явно выбирать `overrideAccess` по назначению операции: `false` для действий от имени пользователя, `true` для обоснованных доверенных служебных операций; не ставить `true` автоматически.
- Не выводить секреты, не коммитить env-файлы с учётными данными. Не менять подключение к базе без необходимости.
- Перед изменением схемы проверь текущий режим PostgreSQL: development schema push или миграции. Не смешивай режимы без описанного перехода; не выполняй сброс базы или разрушительные изменения без согласования.
- Тесты, создающие или удаляющие записи, выполнять только на явно выделенной тестовой базе.
- После изменения схемы генерировать типы; import map обновлять при необходимости. Сгенерированные файлы не редактировать вручную.
- Выполнять проверку TypeScript, lint и применимые проверки. Проверки связей и валидации должны проверять поведение через Payload, а не только форму конфигурации.
- Отдельно сообщать, что реально проверено, что не удалось проверить и что пользователь должен проверить в локальной админке.
- Работать в рамках текущего задания по этапам. Не реализовывать всю спецификацию автоматически.
